# InsightLoop MERN Architecture Migration History

**Repository**: InsightLoop Monorepo  
**Safety Base Tag**: `pre-mern-migration-2026-10-15`  
**Completion Date**: October 2026  
**Final Architecture**: Pure MERN Monorepo (Node.js/Express + React 19 + TypeScript + Turborepo + MongoDB + Redis/WebSockets)  
**Status**: **FINAL: MERN-ONLY (100% Python/Django Decommissioned)**

---

## 1. What Was Migrated

InsightLoop was originally built as a Python/Django monolith backed by MongoEngine and Daphne. Over an 8-phase structured migration program, the entire backend and frontend architecture was migrated to a high-performance, strongly-typed TypeScript monorepo managed with Turborepo and pnpm:

- **Apps & Packages Layout**:
  - `apps/api`: Express 4, native `mongodb` driver (v6), Zod v3 validation, Pino structured logging, native Node 22 WebSockets (`ws`), Nodemailer (STARTTLS), PDFKit invoice generation.
  - `apps/web`: React 19, Vite 6, Tailwind CSS, Recharts, Lucide React, Sonner toasts.
  - `packages/shared`: Shared financial calculation formulas (grand total, balance, transportation, wages, profit margins) shared across backend and frontend with unit-test verification.
- **Decommissioned Python Apps**:
  - `bills`: Invoice and bill generation, status transitions, Kacha/Pakka rules, profit confirmation, PDF rendering.
  - `workers`: Worker profiles, piece-rate material assignments, wage batches, payment tracking.
  - `inventory`: Raw materials, semi-finished, finished goods, warehouse allocations, live inventory counts.
  - `dashboard`: Real-time financial analytics, monthly revenue/expense aggregations, top workers.
  - `upload`: CSV upload, UTF-8 BOM sanitization, validation matrices, batch inventory backfill.
  - `insights`: Business trend anomaly detection, financial ratios, CSV export via `/media/*`.
  - `ai`: Rule-based natural language processing command handler, suggestions, inventory querying.
  - `landing` & `misc`: User authentication (PBKDF2 passwords, Google OAuth2 GIS), user profile, workspace settings, contact form delivery.

## 2. How the Migration Was Verified

Zero degradation, zero downtime, and complete backward compatibility were verified through rigorous gates:

1. **Password Hash & Token Verification**:
   - Django's `pbkdf2_sha256$...` password hashing algorithm was replicated using native Node `crypto.pbkdf2Sync(password, salt, iterations, 32, 'sha256')`. Existing user credentials stored in MongoDB Atlas verify without requiring password resets or rehashing.
   - JWT tokens use SimpleJWT-compatible HS256 signing and expiration conventions, allowing seamless session continuity.
2. **Schema & Document Shape Parity**:
   - The Django MongoEngine schema was exported and frozen to [`docs/migration/django-model-schema.json`](file:///Users/krishnagoyal/Development/personal%20projects/Insightloop/docs/migration/django-model-schema.json) with SHA-256 verification.
   - Automated test [`test/schema_parity.test.ts`](file:///Users/krishnagoyal/Development/personal%20projects/Insightloop/test/schema_parity.test.ts) and CI script [`scripts/check_doc_shape.mjs`](file:///Users/krishnagoyal/Development/personal%20projects/Insightloop/scripts/check_doc_shape.mjs) verify that all MongoDB collections conform to the exact historical document shape, field names, and data types.
3. **True Dual-Stack Parity & Golden Snapshots**:
   - 71 operational checks across 11 functional domains were executed simultaneously against live Django (port 8000) and live Node (port 4000) with zero unauthorized differences.
   - 62 static JSON response fixtures in `fixtures/django_snapshots/` are continuously verified by [`test/snapshot_parity.test.ts`](file:///Users/krishnagoyal/Development/personal%20projects/Insightloop/test/snapshot_parity.test.ts).
4. **PDF Invoice Visual & Character Parity**:
   - Invoices generated by Node's PDFKit engine are verified character-for-character against historical WeasyPrint golden PDFs in [`test/pdf_parity.test.ts`](file:///Users/krishnagoyal/Development/personal%20projects/Insightloop/test/pdf_parity.test.ts).
5. **Route Wiring & WebSocket Reciprocity**:
   - [`scripts/check_wiring.mjs`](file:///Users/krishnagoyal/Development/personal%20projects/Insightloop/scripts/check_wiring.mjs) ensures all 89 registered Express routes are documented in [`docs/migration/public-api-surface.md`](file:///Users/krishnagoyal/Development/personal%20projects/Insightloop/docs/migration/public-api-surface.md) and connected to the web client.
6. **Local Production Boot Smoke Test**:
   - [`scripts/smoke_test.mjs`](file:///Users/krishnagoyal/Development/personal%20projects/Insightloop/scripts/smoke_test.mjs) boots Node in production mode and validates 16 critical health, CORS, auth, inventory, billing, PDF, CSV, and WebSocket flows.

## 3. Safety Tag & Restoration Guide

The immutable git tag `pre-mern-migration-2026-10-15` preserves the final Django-only codebase. Anything removed during cleanup can always be inspected or restored using git.

### Inspect the Safety Tag
```bash
git show pre-mern-migration-2026-10-15
```

### View Migration Diff against the Tag
```bash
# View summary of changes across the migration
git diff --stat pre-mern-migration-2026-10-15..HEAD

# View commit history since the migration started
git log pre-mern-migration-2026-10-15..HEAD --oneline
```

### Restore Old Django Files from the Tag (if needed for reference)
```bash
# Restore legacy Django folder into working tree
git checkout pre-mern-migration-2026-10-15 -- insightloop/

# Restore legacy requirements
git checkout pre-mern-migration-2026-10-15 -- requirements.txt requirements-lock.txt

# Discard restored files when done
git checkout -- insightloop/ requirements.txt requirements-lock.txt
```
